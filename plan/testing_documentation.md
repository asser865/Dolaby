# Dolaby QA & Unit Testing Documentation

This document serves as a cheat sheet to help you remember the purpose of each file and folder related to the Automated Unit Testing setup in the Dolaby project.

---

## 📁 1. The `testing_tools/` Directory
This folder contains all the "machinery" required to run the tests. Keeping it separate ensures your main project root stays clean.

*   **`phpunit.phar`**
    *   *What it is:* The actual PHPUnit application (the industry standard test runner for PHP).
    *   *What it does:* It scans your code, runs the test functions, and determines if they pass or fail.
*   **`phpunit.xml`**
    *   *What it is:* The configuration file for PHPUnit.
    *   *What it does:* It tells `phpunit.phar` exactly where to look for your tests (e.g., "Look inside `../tests/Unit/`") and specifies which files to load first.
*   **`test_dashboard.php`**
    *   *What it is:* The Custom GUI Dashboard.
    *   *What it does:* When you visit this page in your browser (`/testing_tools/test_dashboard.php`), it silently runs `phpunit.phar` in the background, grabs the results, and displays them on a beautiful, modern webpage.
*   **`test_report.html` & `.phpunit.result.cache`**
    *   *What they are:* Automatically generated temporary files.
    *   *What they do:* `test_report.html` holds the raw output generated by PHPUnit, which the dashboard then reads and formats.

---

## 📁 2. The `tests/` Directory
This folder contains the actual test code (the rules and assertions) that verify your business logic is working correctly.

*   **`bootstrap.php`**
    *   *What it is:* The setup script.
    *   *What it does:* It runs exactly *once* before any tests begin. Its main job is to require `includes.php` so that all your classes (`AnalyticsService`, `PromoCodeRepository`) are loaded into memory and available for testing.

### 📂 `tests/Unit/`
This is where individual test files live. Each file tests a specific class in your project.

*   **`PromoCodeRepositoryTest.php`**
    *   *What it is:* Tests the financial discount logic.
    *   *What it tests:* 
        1.  **Percentage Discounts:** Verifies 20% off 1000 EGP = 200 EGP.
        2.  **Max Caps:** Verifies that a 50% discount capped at 150 EGP doesn't exceed 150 EGP.
        3.  **Fixed Discounts:** Verifies a fixed 75 EGP discount applies correctly.
        4.  **Order Total Protection:** Verifies that a 500 EGP discount on a 300 EGP order is capped at 300 EGP (preventing negative totals).

*   **`AnalyticsServiceTest.php`**
    *   *What it is:* Tests the Brand Owner dashboard analytics logic.
    *   *What it tests:* 
        1.  **Total Sales:** Verifies it calculates and returns a valid number (Float).
        2.  **Unique Customers:** Verifies it counts users correctly and returns an Integer.
        3.  **Returning Customer Rate:** Verifies the calculation results in a valid percentage (between 0 and 100).
        4.  **Category Demographics:** Verifies the system correctly categorizes sales into 'Men', 'Women', and 'Kids'.
        5.  **Top Products:** Verifies the system successfully ranks and returns the top 3 selling products.

## 🚀 How to Use
Whenever you make a change to `includes.php` (like changing how discounts are calculated or adding a new analytic metric):
1. Open your browser.
2. Go to `http://localhost/dolaby_v2_SQA/testing_tools/test_dashboard.php`.
3. Click **"Run Tests Again"**.
4. If everything is green, your code changes are safe and didn't break anything!
